# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 72) | Endpoint unconditionally returns `{"status": "ok"}` without verifying database connectivity. | Stop MongoDB or provide an invalid URI; `GET /health` still returns 200 instead of 503. | Added `db.command("ping")` inside a `try/except` block, raising `HTTPException(503)` if MongoDB is unreachable. |
| 2 | Startup / Indexes (lines 20–28) | No indexes created at startup. No unique constraint on `emp_code` or `(emp_code, date)`. | Concurrently creating two identical employees or punch-ins creates duplicates or unhandled 500 errors; query explain plans show `COLLSCAN`. | Created FastAPI `lifespan` handler that idempotently invokes `create_index` for all required unique constraints and query indexes. |
| 3 | `compute_late_minutes()` (line 33) | Grace period check `minutes if minutes > 10 else 0` fails boundary: at 09:40:01 (diff = 601s), `int(601/60) = 10`, which fails `> 10`, incorrectly returning 0 instead of 10. Also compares UTC punch-in with IST shift string. | Punching in at 09:40:01 for a 09:30 shift returns 0 late minutes instead of 10. | Localized punch instant to IST, anchored shift start to attendance date, checked `diff_sec > 600`, and returned `int(diff_sec // 60)`. |
| 4 | `compute_work_hours()` (line 40) | Uses Python's built-in `round(..., 2)` which performs round-half-to-even (banker's rounding) and float representation inaccuracies instead of half-up rounding. | Work duration with second decimals ending in `.x05` rounds down to `.x0` instead of `.x1` (violates R4). | Replaced with `Decimal` division quantized to `0.01` using `ROUND_HALF_UP`. |
| 5 | `compute_overtime()` (line 44) | Does not check the 30-minute minimum threshold (R3); returns any positive minutes. For overnight shifts (`shift_end <= shift_start`), computes shift end on attendance date instead of next calendar day. | Punching out 15 minutes after shift end returned 15 instead of 0. On a 22:00–06:00 shift, punch-out at 06:40 next day returned thousands of overtime minutes. | Added check for `is_overnight` to add 1 calendar day to `shift_end`, and only returned overtime if `ot_min >= 30`, otherwise 0. |
| 6 | `create_employee()` (lines 78–85) | Check-then-insert (`find_one` then `insert_one`) suffers from race conditions. | Concurrent `POST /employees` with identical `emp_code` results in duplicate documents in database. | Enforced database unique index on `emp_code`, catching `DuplicateKeyError` to return 409 Conflict. |
| 7 | `create_employee()` (lines 78–85) | Missing input validation: accepts identical `shift_start == shift_end`, invalid emails, and malformed `emp_code` without 422. `created_at` returned as naive datetime instead of epoch ms. | Submitting `shift_start: "09:00"`, `shift_end: "09:00"` or `emp_code: "invalid"` returns 200/201 instead of 422. | Added Pydantic v2 model validation enforcing regex and shift inequality, and serialized `created_at` to epoch milliseconds. |
| 8 | `list_employees()` (lines 89–96) | `skip = page * page_size` skips page 1 completely (`page=1` skips first 20 items). `total = count_documents({})` ignores `department` filter. Missing sort by `emp_code`. | Requesting `page=1` omits the first 20 records; filtering by department shows total count of all employees in database. | Changed skip to `(page - 1) * page_size`, filtered `count_documents(q)`, added `.sort("emp_code", ASCENDING)`, and serialized documents. |
| 9 | `punch_in()` (lines 100–121) | If employee does not exist, accessing `emp["shift_start"]` raises `TypeError` (500) instead of returning 404. | Punching in for non-existent employee returns 500 Internal Server Error. | Added explicit check returning `HTTPException(404, detail="Employee not found")` before accessing employee fields. |
| 10 | `punch_in()` (lines 100–121) | Check-then-insert allows race condition duplicates for the same employee and attendance date. | Sending two concurrent punch-in requests for same employee on same day creates two attendance records. | Enforced compound unique index `(emp_code, date)` and caught `DuplicateKeyError` to return 409 Conflict atomically. |
| 11 | `punch_in()` (lines 100–121) | Date calculated from server local time `ts.date()`, ignoring IST timezone and overnight shift boundary rules (R1). Also leaked derived `id` built from internal Mongo `_id`. | Overnight shift punch-in at 01:00 recorded under next calendar day rather than previous day's shift date; response contained internal `id`. | Implemented `get_attendance_date()` following R1 overnight rules in IST, and serialized response without internal Mongo `id`. |
| 12 | `list_attendance()` (lines 125–151) | Fetches entire collection into memory (`list(find(q))`), crashing or timing out on 100,000 records. Missing secondary sort key `emp_code` ascending. | Querying attendance on 100k records causes memory exhaustion and latency spikes; secondary ordering is nondeterministic. | Replaced in-memory slicing with Mongo cursor `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` backed by compound index. |
| 13 | `list_attendance()` (lines 125–151) | Missing validation for date range order (`date_from > date_to`). | Passing `date_from=2026-06-30&date_to=2026-06-01` returns empty 200 list instead of 422 validation error. | Added validation check raising `HTTPException(status_code=422)` when `date_from > date_to`. |
| 14 | MongoClient & Datetimes (lines 22–25) | `MongoClient` initialized without `tz_aware=True`. Datetimes stored and read as naive objects, causing timezone skew. | Instants compared inaccurately against UTC boundaries or stored with local offsets. | Initialized `MongoClient` with `tz_aware=True`, standardized all database instants to UTC BSON dates, and converted to integer epoch ms at boundaries. |
| 15 | `list_attendance()` (lines 125–151) | Returns raw BSON `datetime` objects for `punch_in`/`punch_out` instead of integer epoch milliseconds, and fails to validate `status` parameter against allowed enum values. | Fetching attendance returns ISO date strings violating OpenAPI integer epoch ms schema; passing invalid `status` query string returns 200 with empty list instead of 422. | Added serialization converting all datetime fields to integer epoch milliseconds, and added FastAPI status enum validation returning 422 for invalid statuses. |

### Examined and Decided Was Not a Defect
1. **Client-provided `emp_code` in `POST /employees`**: Checked whether `emp_code` should be auto-generated by the server. OpenAPI and `DATA_MODEL.md` explicitly state that `emp_code` is a client-provided, customer-generated business code (format `EMP` followed by 4–6 digits), not an auto-incrementing ID or MongoDB `_id`.
2. **`history` field initialized to empty list `[]` during punch-in**: Checked whether punch events should append to `history`. The specification confirms `history` is exclusively an audit trail for manual corrections (`PATCH`); punch-in and punch-out are original events and must never write to it.
3. **`load_dotenv()` at top-level**: Checked if local `.env` variables would accidentally override production environment variables. Python `load_dotenv()` defaults to `override=False`, ensuring system-injected environment variables take priority as required.
